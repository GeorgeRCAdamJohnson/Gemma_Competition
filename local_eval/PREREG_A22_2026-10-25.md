# PRE-REGISTRATION — A22 Class-1 contradiction fixes on 31B, 2026-10-25

Written BEFORE the kernel is pushed or run. Nothing below may be edited after the run starts.

## Question
Does fixing the four direct contradictions in the control prompt raise the resolve rate
on flipping rich tasks? (Contradictions = the model cannot obey both orders.)

## Why these four (evidence, A21-run trace forensics + 129-run)
1. TWO LOCATE DEADLINES: line 26 "AT MOST 3-4 tool calls" vs trigger table
   "tool_calls_remaining <= 14". Measured: first_edit averages call 19; 90% of 129-run
   runs violate one or both. Likely ignored BECAUSE they contradict.
2. ONE EDIT vs N EDITS: line 40 "1 edit_file call" vs line 23 "apply EACH" for
   multi-item fixes. 38/129 tasks have multi-file gold (3/38 solved, p=0.0019).
3. WHAT'S FREE: line 4 "get_status is FREE" (verified true: count_tool_call=False in
   harness) vs line 20 "budget limits READS AND EDITS equally" + "still allowed to edit".
   The 3777 trace: model QUOTED line 20, attempted edit at 0 calls, got BudgetExceeded,
   retried twice, died. 14 BudgetExceeded errors in the 129-run.
4. "IMPLIES" vs "EXACT": line 33 invites inference then forbids paraphrase in the
   same bullet.

## Arms (four single-span substitutions of the kernel control, byte-verified)
- A3 control: kernel prompt sha 8641826db79b (7505 chars) — the 129-run prompt.
- A22: sha bd61ca21b91e (7820 chars, +315 / +4.2%). Built by prompts/_build_a22.py:
  1. locate deadline -> one deadline (the trigger table)
  2. edit count -> ONE per file when multi-file
  3. free calls -> "get_status and submit_patch are the ONLY free calls" + hard
     edit deadline before 0 (names BudgetExceeded)
  4. "implies" -> "states"

## PRIMARY metric

two-sided, alpha 0.05. Canary and 3278 reported separately.
