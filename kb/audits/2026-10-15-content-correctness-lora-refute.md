# Refute audit — content-correctness LoRA (multi-layer)

## 1. Suggestion restated
Train one low-rank, broad-span 31B LoRA on clean self-distilled passing software-engineering trajectories so the unchanged v6w agent writes more correct edit content. The proposal keeps v6w @ 0.15 live, requires a held-out baseline and no pass-to-pass regression, then sends only a winner to the FREE rich gate. It blocks training until a multi-layer effect probe and a trustworthy held-out no-adapter baseline exist. [MEASURED: `Gemma/kb/proposals/2026-10-15-content-correctness-lora-recipe.md`]

Prior objectives were edit discipline, localization/commitment, or FastAPI idioms. [MEASURED: `Gemma/GEMMA_EXPERIMENT_LOG.md:L9418-L9500`; `Gemma/PAPER_FINDING1_DRAFT.md`]

## 10. Verdict rationale
**NEEDS-DATA.** Pass 1’s final verdict is retained, but three load-bearing rationales are narrowed or overturned:
- Existing v2 runs prove a large **adapter-artifact** effect, not that the proposed controlled multi-layer effect probe is redundant or that broad span is the causal mechanism.
- Passing trajectories do contain correct edit-content supervision. Whether that signal generalizes enough is unknown; “cannot carry correctness signal by construction” is false and the dossier’s broad capability warning is not an experiment on this proposal.
- The 150–200 L4×4-hour harvest estimate is an unsupported projection because neither pass yield nor per-row throughput has been measured on the proposed external-issue population.

The blocking facts remain measured: no trained candidate, no exact held-out list, only four rp-4 gold-valid rich tasks, no local 31B agent arm, and no logged result from the proposed broad-adapter probe. The novel content-correctness idea should be debugged through the four measurements in §9, not rejected. [MEASURED blockers; INFERRED verdict]
