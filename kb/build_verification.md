### Lock bug found and fixed during verification  [MEASURED]
First idempotence attempts returned exit 8 ("build lock held") on the second build because `kblib/lock.py`
over-reported pid liveness (Windows `OpenProcess` can succeed for a dead/reused pid) and the stale-age was
too long, so a leftover `.build.lock` from an interrupted run was never reclaimed. Fixed: liveness now also
checks `GetExitCodeProcess` (alive only if `STILL_ACTIVE`), defaults to "dead" when ctypes is unavailable,
and the stale age is 90 s (a build takes ~13 s). After the fix, back-to-back builds succeed, update the
stamp, and leave no lock. Unit test `test_lock_exclusive` + `test_lock_no_os_kill_in_source` pass.
