## 2. The three claims most likely wrong, and the settling test

1. **A1, “only 59 truly solvable / 34 dead.”** The evidence measures a lower bound, then labels it a ceiling. **Settling test:** in one immutable copy of the official evaluation image, run gold and empty controls for every task with exact scorer semantics. For every collection-blocked task, run a legal minimal source-side dependency shim without changing tests. Classify `gold-valid`, `empty-valid`, `environment-blocked under unchanged source`, and `proved impossible under submission rules` separately. The last class currently has no evidence.

2. **C1, “noise is ±2 tasks per 129,” and the downstream C2 use of that number.** It is based on one identical-config pair. **Settling test:** at least 20 exact replicas, or a preregistered sequential design that stops when a confidence interval on the run-level SD is narrow enough. Lock task set, prompt hash, model build, sampler, concurrency, caps, scorer, and environment. If that is unaffordable, stop making numeric noise-floor claims.

3. **F1, “the decode sweep cleanly yielded four mechanical wins/noise.”** The descriptive JSONL exists, but baseline and arms used different scorer versions, the clone was dirty, the frozen cohort changed, and cache provenance is incomplete. **Settling test:** rerun uncached from a clean clone with all 12 frozen tasks, a symmetric preregistered timeout rule, one scorer version, and provenance-complete cache keys. Require repeated task conversions or a minimum held-out effect; a one-call median shift on n=5 cannot be a win.

## 4. What is actually established

- **Measured:** One corrected whole-file replay artifact gives 30 gold-valid rich tasks and one gold-valid requests task; the Kaggle CPU fastapi replay gives 29. The empty-patch artifact passes only `requests_6644`. Therefore **59 tasks are verified non-degenerate gold-valid under those replay procedures**. This does not establish a 59-task ceiling.
- **Measured:** The three local request resolves `requests_7309`, `requests_7315`, and `requests_7427` are false positives. Independent replay produces clean assertion failures, and the failed editable-install/src-layout mechanism explains them well.
- **Measured:** Current local ca5-family draws record 12, 14, and 14 solves; after removing the same three request phantoms they contain 9, 11, and 11. The real Kaggle E4B run records 10/129. Similar totals do not prove backend fidelity.
- **Measured:** One empty-prompt run is 2–4 corrected solves below three ca5 runs and misses three tasks solved in all three ca5 runs. The prompt's causal value and the probability that those tasks remain absent under repeated no-prompt draws are unknown.
- **Measured:** The modified definition rule was never executed as a repo-wide definition grep in seven traces. Three traces used a cheaper single-file form. Both resolves occurred without the rule.
- **Measured:** The decode-sweep rows contain no credible held-out decode gain. The four nominal wins are one task or one-call timing movements. The experiment's mixed scorer, changed cohort, dirty clone, and incomplete cache provenance prevent a stronger inference.
- **Strong inference:** Equal-weight binary scoring with truncation has a unique denominator of 58 among N=10…2000 for the observed public-score support. It remains conditional on that scorer family.
- **Not established:** a 34-task impossible set, a 59-task maximum solvable set, a ±2 run noise distribution, local-to-Kaggle effect transfer, a +2–4 prompt treatment effect, or the 13/44 retrieval-error proportion.

## 5. What to do next

1. **Repair the evidence boundary before another model claim.** Freeze a task-level benchmark ledger generated from raw official-image controls. Keep separate columns for gold-valid, empty-valid, dependency collection failure, agent-induced import failure, and replay uncertainty. Mark obsolete artifacts such as `replay_gold129.json` and the 1/9 `results/summary.json` so automated analyses cannot consume them accidentally.

2. **Fix verification deterministically without GPU.** Make editable-install failure fatal, or explicitly put `/workspace/src` on `PYTHONPATH` for src-layout repositories. Record imported package paths in every test output. Replay every resolved patch. This removes the known phantom class and turns “exactly three” into a testable statement.

3. **Do not spend the daily scored slot on a change selected by the current local sweep.** The sweep does not have trustworthy comparative provenance. Keep the existing E4B bundle unchanged until a candidate passes the required free rich gate under one clean scorer and a pre-registered effect-size bar.

4. **Use one unchanged E4B resubmission as an external variance measurement only if Kaggle permits retaining the best score and the free-gate protocol does not require a new gate for an unchanged artifact.** Pre-register the interpretation before submitting: an exact artifact/hash repeat is a replication, not an optimization. One repeat will not estimate a distribution, but it tests whether the E4B leaderboard outcome is visibly stochastic. Do not use main-track score variance as a substitute for E4B evidence.

5. **When GPU access returns, prioritize one deep, externally judged structural change.** The strongest mechanism evidence is E1: prose did not produce repo-wide definition search. Test a structural precondition that records or enforces definition-site localization before edit. Use a clean rich-only free gate, one change, repeated baseline and treatment, and a bar requiring task conversions plus compliance. A compliance-only shift is not enough.

6. **Preserve the current prompt for now.** D1 does not prove a +2–4 effect, but the only available direction favors ca5, and removing it has no evidentiary upside. Additional prompt rewrites are lower priority than verifier correctness and structural enforcement.

7. **If no GPU budget returns, spend effort on CPU-safe testable work rather than narratives:** repair the replay/import provenance, publish the 44-event process ledger, and statically audit cache keys and result manifests. With one scored slot per day and no trustworthy local selector, unsupported prompt changes have negative expected information value.
